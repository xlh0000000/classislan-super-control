# ClassIsland Control 使用文档

面向学校信息教师与运维：从一套空平台，到管住一批教室里的 ClassIsland。文中按钮名、页签名照实际界面写。

## 0. 先记住这套模型

| 概念 | 位置 | 作用 |
| --- | --- | --- |
| 设备 | 装了本插件的 ClassIsland | 被管的一端，按轮询或长连接联系集控台 |
| 配置库 | 侧栏「配置」四页 | **只存内容**：课表、组件布局、自动化流程、插件设置 |
| 策略 | `/policies` | **唯一的下发入口**：把内容 + 管控 + 锁定打包发布到某个范围 |
| 任务 / 自动任务 | `/tasks` `/automation` | 让设备做动作（重启、提醒、刷新天气…），立即、定时或出事时 |
| 审计 | `/audit` | 所有写操作留痕，哈希链可验伪 |

配置库里的条目本身不会自己上设备：只有策略按节引用它，它才会随策略下发。「改了没生效」只需要看策略。

## 1. 部署与首次初始化

要求 Node.js ≥ 22.22.2（推荐 24.15+）。

```bash
npm ci && npm run build && npm start     # 开发用 npm run dev
docker compose up -d --build             # 或用容器
```

- 数据默认落在 `./data`（SQLite WAL + 服务端签名密钥），换目录设 `CLASSISLAND_CONTROL_DATA_DIR`。
- 公网暴露前：由可信反向代理提供 HTTPS，并设置高熵的 `CLASSISLAND_CONTROL_BOOTSTRAP_TOKEN`。
- 第一次访问会跳到 `/setup`：填部署引导令牌（生产环境需要）、学校名称、管理员账号（默认 `admin`）与密码（≥12 位），点「完成初始化」。初始化成功后 `/setup` 永久关闭，之后只能从 `/login` 进。
- 备份与恢复：`npm run backup` / `npm run restore`（见 §12）。

## 2. 账号与角色

角色是单值的，管理范围是一条「组织水位线」：范围外的目标一律按不存在处理（返回 404 而不是 403），所以不同人看到的树天然断开。

| 角色 | 能做什么 |
| --- | --- |
| 所有者 | 全部；只能通过「转移」产生，不在用户下拉里授予 |
| 管理员 | 全部业务读写：策略、配置、任务、设备、组织、接入、用户、系统、审计 |
| 操作员 | 设备与任务：看总览/设备、改设备与连接、建任务、点名只读、看崩溃与插件，**不能发策略、不能改配置库** |
| 审计员 | 只看审计、崩溃、插件 |
| 只读 | 所有读，不含任何写 |
| 教师 | 只看自己被绑定的设备：点名读写、把配置库里的课表套到自己那台机上 |

- `/users`：新建用户、批量新建教师（每行「用户名 显示名」），批量建的账号带初始密码，教师首次登录会被强制改密。
- 侧栏底部「改密」随时改自己的密码，新密码 ≥12 位。

## 3. 先搭骨架：组织、标签、楼栋

设备接入之前把这三样定好，之后所有下发、任务、点名设置都挂在这三层上。

- `/organization`：「新建节点」建学校 → 年级 → 班级的树（弹窗里选父节点、填节点名称）；「新建标签」建跨结构的分组（如「一体机」「有麦克风故障」，带颜色）。标签是设备维度的多选集合，一台设备可挂多个。
- `/`（楼栋部署）：「＋ 楼栋 / ＋ 楼层 / ＋ 教室 / ＋ 设备」，双击改名，行内删除；教室卡里能看到进了哪几台，点开「教室：X」弹窗可搜索、加入、移出。一台设备只能属于一间教室。
- 楼栋页支持在楼层/教室上按下拖动框选多台，选中结果写进全局「目标」，与策略页、任务页共用同一份选择。
- 楼栋页顶部还有两枚常用的：**「全选本楼栋」**把当前这栋的设备整组加进手选清单（再点一次整组撤掉，按钮跟着变成「取消全选本楼栋」）；**「全校」**是一个勾选框，勾上即把目标切成全范围，不必先开「选择目标」弹窗。

## 4. 接入新设备

`/enrollment`（需要「接入」权限，即所有者与管理员）。两种凭据：

- **01 一次性接入码**：只能注册 1 台。
- **02 批量接入码**：同一个接入码可注册 2–1000 台，机房统一装机时用。

创建时可填：

| 字段 | 说明 |
| --- | --- |
| 有效时间（分钟） | 5–1440，过期即作废 |
| 允许接入设备数 | 仅批量码，2–1000，按次消耗 |
| 绑定组织 / 绑定标签 | 设备一注册就落在这些分组里，不用事后补 |
| 加入时自动下发 · 下发策略 | 选一份**已发布**的策略修订做底稿；历史修订也能选，会标「（历史修订）」。不绑定就是裸设备，之后照常按作用域解析上层策略 |

想要新机器一上线就带上本班课表：把那份课表放进配置库，在策略里按「档案与课表」节引用它，再把这条策略选成下发策略。凭据自己不再逐类绑配置——接入时能下发的只有这一份策略。

点「生成接入码」，结果只弹一次，先「复制接入码」再关。

设备端：在 ClassIsland 的「设置」里找到本插件，填「服务器地址」（支持 http/https）、「设备名称」，首次注册时填「一次性接入码」，点「保存并连接」。

之后发生的事：

- 设备出现的同一刻，那份底稿会被落成这台机自己的**设备级策略**，名字是 `接入下发 · <源策略名>`，锁也一并带过来；管理员不需要再点一次下发。
- 同一台机器重复注册（同一公钥 + 同一凭据）按幂等重放处理：不重复扣次，也不会重发这份预下发策略。
- 已吊销、已过期、已用尽的凭据一律拒绝。
- 设备上没有退出集控的入口：服务器地址与设备身份会被折回锁定值，只有集控端下发「解除集控」且收到设备回执，本机才清除身份。

## 5. 配置库：只管内容

侧栏「配置」四个入口分别是 课表 / 组件布局 / 自动化 / 插件设置（对应四种类型：档案与课表、组件布局、自动化工作流、插件设置）。同一组里还有「点名」，那是平台侧的点名单元设置，不经过策略，见 §8。

- 「新建课表 / 新建组件布局 …」：填名称、选类型，可以「导入配置文件（可选）」直接吃现成 JSON（ClassIsland 导出的自动化配置是裸数组，入库会自动包成 `{ "workflows": [...] }`）。
- 行上的按钮最多三枚：「编辑」「档案设置」（仅课表）「修订」。**这里没有下发按钮**——内容是内容，交付是策略的事（§6）。
- 课表类配置的「编辑」会跳到 `/timetable`：时间轴画布上拖动色块改时长、整块平移，按住拖动框选多条，块尾「＋」接续添加，右侧「编辑时间点」检查器改起止与类型；`课表 / 科目 / 时间表` 三个页签分别管排课、科目库（名称/简称/任课教师/户外）与作息表（可「生成标准作息」「复制时间表」）。改完点「保存为新修订」。
- 其余三类的「编辑」打开可视化编辑器，带「可视化 / 源码」两个页签，可视化没覆盖到的字段直接在源码页签改 JSON。
- 「修订」弹窗：选起始修订与目标修订「比较差异」，或「回滚到这里」。回滚不是删除历史，而是照旧版重做一份新修订。
- 设备上的课表可以回收进配置库：设备详情 → 「课表」→「采纳为配置」，之后就能被策略引用发给别台。

## 6. 策略：唯一的下发入口

### 6.1 新建并发布

`/policies` →「选择目标」→「新建策略」。弹窗是宽版的引导流程，分五个选项卡，页脚「上一步 / 下一步」按顺序走：

1. **目标**：名称与优先级；「发到哪一路」列出已选目标（没选就在这里或页面右上「选择目标」里挑）；「怎么落到已有策略上」开关「追加到已有策略」——开着就是在该作用域现有文档上叠加，关掉就是整份替换。
2. **内容**：四节各一个开关 + 下拉，下拉列的是配置库里同类型的条目（显示「名称 · 第 N 版」）。选定后策略里存的是 `{ "profile": { "$config": "<配置ID>" } }`，设备取用时才展开成配置本体——**配置库更新一版，引用它的策略下一次轮询就带出去**，不必重发策略。
3. **设置管控**：「设置覆盖」每项三态 不动 / 锁定 / 解锁（如 应用设置、调试菜单、禁止本机退出集控 等）；「设置页管控」逐页 不动 / 放开 / 只读 / 隐藏。
4. **时间**：不调控 / 固定偏移 / 自动对齐集控端时钟 / 每日自动递增（可填基线秒数）。
5. **锁定与原文**：加 JSON Pointer（有 `/profile`、`/settings` 等预设 chips），或直接改整份文档。

后四页各自顶部有一个「沿用已有修订」下拉，**候选只列你选中的那几路作用域挂过的版本**（标签页会写成「标签 · 某某 · 第 N 版 名称（生效中）」），每页单独选，互不影响。选中后紧跟着把接过来的东西显式列出来：

- 能用本页控件表达的，直接落到控件上并逐条列出（设置页如「调试菜单 → 锁定」「基本 → 只读」，时间页如「设备时间 → 每日递增 +5 秒，基线 +60 秒」）。
- 控件表达不了的（写死的整节、整节的配置引用、插件自己写的节、锁清单），照原样带走，列表里以原文 JSON 或路径显示，对应控件旁标「已沿用整节原文」。
- 「取消沿用」退回本页手工填写。在已经沿用上的那一页动手改控件，那一页沿用的原文即刻作废，以你手工填的为准。
- 「锁定与原文」页另有「四页一起照搬这一版」，一次把内容、设置、时间、锁四页全换成那一版。

底部「发布到 N 台设备」：给每个选中目标各生成一份新修订，并推进期望状态版本；设备下一次联系时生效。**一个范围同时只有一条生效中的策略**——对同一个目标再发一条，会把它原来那条顶成历史，不是叠加。

### 6.2 四层怎么合并

- 顺序：**学校 → 组织（根到叶）→ 标签 → 设备**，越靠后越优先，所以一台机器的设备级策略最硬。
- 同一层内多条时按 `优先级`（−1000…1000，数值大的后合并、因此赢）→ 修订号 排。
- 合并是深合并：对象逐层递归，**数组与标量整份替换**（想改数组里一项，得给整个数组）。
- 「追加到已有策略」在服务端存的是合并完成后的文档，读的时候不再重算。

### 6.3 锁定是给谁用的

`locks` 里的指针保护的是**声明它的那一层写下的值**，挡住更具体的层去改。例如学校层锁 `/settings`，那么组织、标签、设备层都改不动设置节。

锁只作用于服务端的层间合并。例外是设置节：宿主会用签名快照硬锁，学生本地改 `Policy.json` 重启后仍被折回。

### 6.4 版本、并发与回退

- 修订号全局单调递增；发布走乐观并发，若你打开编辑器后别人又发了一版，提交会返回 409「策略已在别处更新」。
- 任何策略激活、以及设备与组织/标签的成员关系变化，都会推进期望状态 epoch。因此「摘掉一个标签导致有效修订回退」这种情况，设备也会重同步，不会因为号码变小而忽略。

### 6.5 看这一版到底管了什么

`/policies` 的主视图是**一面按作用域分组的状态墙**（全校 / 组织 / 标签 / 设备 四组），不是修订流水账：一路作用域一张卡片，卡上写「生效中 · 第 N 版 名称」、管到哪几节、锁了几处、这一路覆盖几台（台数按当前设备台账现算，删掉或停用的不再计入）。没有生效策略的路会标成「当前没有生效策略」，仍然留在墙上。

- 点卡片 → 弹窗「这一版策略的内容」：挂在哪（作用域与对象名）、写法（整份替换 / 追加覆盖）、优先级、基于哪一版、谁发的、时间；「管到哪些内容」逐节写明是**引用配置库里的哪一条第几版**还是**写死在这一版里**；再往下是锁定路径清单与格式化原文（标题带哈希前缀）。
- 卡片底部「历史 N 版」→ 二级抽屉，列这一路挂过的每一版（新的在上，当前那版标「生效中」，其余标「已顶替」）；行上带这一版的节清单与「锁 N 处」，点其中一行同样打开上面那个详情弹窗。锁随修订一起存档，所以已顶替的旧版也答得上「当时锁了什么」；只有优先级仍挂在会被后一版覆盖的那条记录上，抽屉里只在生效那一版显示。
- 设备详情 → 概览 →「生效策略明细」：这台机命中了哪几层、各自的优先级与锁、生效修订 vs 设备已应用修订、同步状态、偏差次数，以及每一节被标记成 已应用 / 跳过 / 失败。

### 6.6 想撤下某项

策略修订不删除，旧修订只作为历史保留（在该作用域的「历史 N 版」抽屉里，标着「已顶替」）。要撤下某项内容，就在同一作用域再发一版不含该项的策略；设置与时间两节在设备侧是「缺省即回退」——文档里不再出现 `settings` / `time` 时，设备会解锁并回本机原值。

## 7. 任务与自动任务

- `/tasks`「创建任务」：选能力（高风险能力会标注，如应用重启与退出）、有效时间（1–10080 分钟）、下发方式（一次全发 / 固定批次 / 按比例分批）、失败率上限、最大并发，再「选择目标」并填命令内容（可展开「高级：直接编辑命令内容」）。提交即「创建并下发」。
- 灰度：分批任务里任一批失败就停止后续批次；超过失败率上限会取消剩余目标。行操作有 暂停 / 继续 / 取消 / 详情，详情里看批次、逐台执行结果与审计时间线。
- `/automation` 两个页签：
  - **周期调度**：每天 / 按星期 / 每月几号 / 固定间隔（5–20160 分钟），指定触发时刻；服务停过机只补跑一次。行上可 暂停 / 恢复 / 立即执行 / 编辑 / 删除。
  - **事件触发**：事件是「设备离线超时」或「崩溃次数阈值」（窗口内次数），监控范围选全校或某组织，带冷却分钟（默认 60）；不指定动作目标时，命令只发给出事那台。命令内容里可用 `{{deviceName}}`、`{{deviceId}}`。

## 8. 点名

- `/rollcall`「新增名单」：名单名称、作用范围（全校 / 组织 / 设备）、姓名列表（每行一个）。设备上的悬浮窗不能本地改名单。
- 「点名默认设置」：点名悬浮窗（显示/隐藏）、「多人」按钮（显示/隐藏）、抽中时提醒、单人停留秒数（1–120）、多人停留秒数（2–300）。**逐字段独立继承**：设备 → 最近的上级组织 → 全校 → 设备本机设置；填了就下发，整层留空等于把这层交还给上级，「清除本层设置」即删掉这一层的行。作用范围没有标签。
- 悬浮窗按钮是「抽人」（抽 1 人）和「多人」（下拉 2–6 人，停留时长为多人基准 + 每多一人 1 秒）。「多人」按钮关掉后窗上只剩「抽人」一颗，占满整行，一次只抽一个。
- 设备详情 → 点名：可「查看当前名单」「保存为本机名单」「删除本机名单」「保存并下发」「清除本机覆盖」。
- 教师登录时这一页变成「我的点名名单」，只跟着自己绑定的设备。

## 9. 崩溃上报

四类来源：未处理异常 / 后台任务异常 / 界面线程异常 / 程序退出。设备端先写本地待报队列，随轮询上报，服务端确认后才清空——断网期间的崩溃不会丢。每台保留 200 条、留 90 天，按「异常类型 + 归一化堆栈」指纹归组。

`/crashes` 顶部可切 7 / 14 / 30 / 90 天，点分组看堆栈明细，可按设备筛选（`只看 X`），支持「清除记录」「清除该分组」。

## 10. 插件升级（静默）

`/plugins` 三个页签：发布版本 / 目标版本 / 逐台设备。

- 「上传插件包」传 `.cipx`（需要插件写权限且是全校范围账号）：服务端读出包内 `manifest.yml` 的插件 ID 与版本，并记录大小与 SHA-256；下载时的摘要、大小与包内版本由设备端比对。行上可「设为当前」「撤回」。
- 「指定目标版本」：作用范围选 全校 / 组织 / 标签 / 设备，填目标版本号，「保存并下发」；「取消该范围」把决定权交还上层。解析顺序：**设备 > 标签 > 最近的组织祖先 > 全校 > 当前发布版本**。
- 设备侧全自动：后台下载 → 校验摘要与大小 → 暂存 → 等到空闲窗口（不在上课与课前，且距下节课 ≥2 分钟）自行重启换包；同一版本连败 3 次会暂停，10 分钟后重试。想让某个班先升，就把目标版本设到那个组织。
- 回滚就是设成旧版本号，走同一条通道。
- 「逐台设备」页签按版本看分布：已在用 / 待升 / 等待重启 / 失败。
- 「上游版本检测」（发布版本页签顶部）：服务端定时去 GitHub 取最新发布标签，界面显示「上游最新 x.y.z.w」与库里最新版本的差。标签 `v0.1.7` 会补成 `0.1.7.0` 再比，带 `-beta` 之类后缀的标签不认。
  - 默认每 30 分钟查一次（可调 10–1440 分钟），也可「立即检查」；检查只在后台跑，抓取不占数据库写锁。
  - 镜像地址一行一个，按顺序试，都不通才直连 `api.github.com`；只收 https 的干净站点前缀，内网地址与云元数据地址直接拒。
  - 「拉取 x.y.z.w」把那一版的 `.cipx` 经同一串地址取回，按上传路径同一套标准验收（大小、清单 ID、清单版本必须等于检测到的版本、上游给了摘要就比摘要），通过后存成一个发布版本——**不设为当前版本**，要不要全校跟着升仍由「设为当前」决定。
  - 关掉检测会清掉上一次的结果，界面不再举着一个没人确认过的「新版本」。

## 11. 设备管理细节

`/devices` 表格列：设备 / 组织 / 状态 / 连接 / 插件·宿主 / 最后联系。逐台的操作都在详情弹窗里，列表上不放批量按钮。

设备详情弹窗的页签：概览 / 连接 / 课表 / 点名 / 教师 / 能力 / 命令。

- **连接方式**由集控端逐台指定：`定时轮询`（间隔 5–30 秒）或 `长连接`（5–60 秒重连退避），两者提交同一份签名信封。列表里的「在线」= 未被禁用且最后联系在 45 秒内。
- **停用**：设备轮询被拒、未发出与已发出的命令一并取消；改名这个动作会顺带把设备恢复启用，停用中的机器别顺手改名。
- **解除集控**：需要设备声明了该能力、当前未被禁用、同时只允许一条在途，命令 24 小时有效、最多 3 次尝试；设备在收到终态回执后才清除身份与封条。
- **删除设备**：只删服务端记录（连带标签、命令、能力快照、升级目标），**不会**动教室里的机器——要让真机退出集控，先「解除集控」。
- **教师绑定**：在「教师」页签选账号「绑定」，教师自己登录时可解绑。

## 12. 审计与备份

- `/audit`：谁在什么时候对什么做了什么。写操作与业务数据在同一事务里落链，后台每 60 秒对链头签名并存检查点，事后改动可查；翻页用「加载更早的记录」。
- `/settings`：看服务状态与备份列表（每条标「校验通过 / 失败」），「创建备份」产出一个 bundle：SQLite 在线快照 + 服务端签名私钥 + 逐文件 SHA-256 清单。
- 恢复必须离线执行（`npm run restore`），且签名私钥与数据库必须一起恢复，只回数据库会让历史签名对不上。

## 13. 排查：改了策略，设备没变

按这个顺序看，基本三步内能定位：

1. **策略页点这一版详情**：挂的目标是不是这台/这个范围？要改的节有没有被上层锁住？引用的是配置库哪一条第几版？
2. **设备详情 → 生效策略明细**：命中了哪几层、生效修订与已应用修订是否一致、同步状态是 `已同步` / `有偏差，待重同步` / `离线未上报` / `已禁用`、偏差次数、每节的 已应用/跳过/失败。
3. **设备是否还在联系**：设备列表「最后联系」；`/overview` 的「策略偏差」与设备群视图能一眼看出是一片还是一台。
4. **发布是否落地**：`/audit` 找这次发布记录；没有记录就是没发出去（权限或范围不够）。
5. **机器上确认**：设备端插件设置页会显示 已应用策略、集控端锁定、时间偏移、最近同步。

## 14. 常见问题

- **配置页怎么没有下发按钮了？** 统一走策略。一次发布可以同时带内容、管控与锁定，也避免出现「同一台机器两处状态」的排查黑洞。教师仍可在设备详情里选一份课表「下发到本机」，底层同样是给这台机生成一份设备级策略修订。
- **发布时提示 409。** 有人在你打开编辑器之后又发了新版。刷新列表、重做改动再发。
- **刚改了设备的组织或标签，策略没跟上。** 成员关系变化会推进期望状态 epoch，设备等下一次同步就会带来新策略，快慢取决于它自己的同步间隔。
- **想给机房单独一套布局。** 建一个标签或组织节点，把机房机器移进去，再对该范围发一条含该节引用的策略；需要盖住全校默认时，把优先级调高。
- **想让新装的机器一上线就是本班配置。** 先把本班的内容发成一条策略（可按班级组织或标签为范围），再在 `/enrollment` 生成接入码时选「下发策略」并选中它，注册瞬间自动生效。
- **只读角色为什么看不到目标多选？** 只有策略与任务这类发布动作会消费目标选择，进不去那些页的账号不会看到多选控件。
